# Курсовой проект «Реализация программы контроля облачной инфраструктуры»

## 1. Назначение программы

Программа на языке C предназначена для контроля состояния облачной инфраструктуры по последовательности телеметрических измерений. Программа:

- хранит наборы телеметрических измерений по трём компонентам в одномерных массивах (без использования двумерных массивов);
- вычисляет производный показатель динамики $Q[i]$ для произвольного периода сравнения $k$;
- обрабатывает пропуск первых $k$ элементов, деление на ноль и недопустимый аргумент логарифма;
- определяет состояние каждого компонента по порогу $L$;
- проверяет правило инцидента и формирует журнал инцидентов;
- предоставляет текстовое меню для выбора набора данных и настройки параметров анализа.

## 2. Индивидуальный вариант (вариант 25)

| Параметр | Значение |
|---|---|
| Компоненты | WEB, DBS, IOP |
| Порядок записи | А: время, компонент, значение |
| Разделитель | запятая |
| Тип последовательности | 4: произвольный порядок, возможны пропуски измерений |
| Производный показатель | логарифм отношения |
| Период сравнения $k$ (по умолчанию) | 1 (настраивается от 1 до 4) |
| Порог $L$ (по умолчанию) | 1.0 (настраивается положительным числом) |
| Параметр $D$ | 10 |
| Правило состояния | выход за диапазон $[L_{\min}, L_{\max}]$ |
| Правило инцидента | все три компонента одновременно в состоянии, отличном от «НОРМА» |
| Структура `Incident` | `int time; int type;` |

Инфраструктурные компоненты:

- **WEB** — веб-сервер, обслуживающий внешние запросы;
- **DBS** — сервер базы данных;
- **IOP** — подсистема ввода-вывода.

## 3. Математическая модель

### 3.1. Производный показатель

Для каждого компонента вычисляется логарифм отношения текущего значения к значению, отстоящему на $k$ измерений назад:

$$
Q[i] = \ln\left(\frac{X[i]}{X[i-k]}\right).
$$

Если $i < k$, пара для сравнения отсутствует и измерение пропускается. При $|X[i-k]| < 10^{-9}$ фиксируется ошибка деления на ноль, а при $X[i] / X[i-k] \le 0$ — ошибка недопустимого аргумента логарифма.

### 3.2. Правило состояния компонента

При $L_{\min} = -L$ и $L_{\max} = L$ состояние компонента определяется так:

$$
S_i =
\begin{cases}
1, & Q[i] < L_{\min} \ \lor \ Q[i] > L_{\max},\\
0, & L_{\min} \le Q[i] \le L_{\max},
\end{cases}
$$

где $1$ соответствует состоянию «ТРЕВОГА», $0$ — состоянию «НОРМА».

### 3.3. Правило инцидента

Инцидент фиксируется, когда все три компонента на одном отсчёте находятся в состоянии «ТРЕВОГА»:

$$
I(t) = A_{\text{WEB}}(t) \land A_{\text{DBS}}(t) \land A_{\text{IOP}}(t),
$$

$$
A_c(t) = \left(Q_c(t) < L_{\min}\right) \lor \left(Q_c(t) > L_{\max}\right).
$$

## 4. Организация данных и структура программы

### 4.1. Формат исходных данных

Контрольный набор варианта 25 в исходном представлении:

```text
4,WEB,48.8, 2,DBS,55.4, 2,IOP,29.5, 5,DBS,54.8, 3,WEB,48.3, 5,WEB,49.3, 5,IOP,32.6, 4,DBS,51.4, 1,IOP,30.2, 1,DBS,57.4, 3,IOP,34.1, 1,WEB,41.9, 3,DBS,53.4
```

Всего 13 записей по 5 отсчётам (у `WEB` пропущен отсчёт 2, у `IOP` — отсчёт 4):

| Компонент | t = 1 | t = 2 | t = 3 | t = 4 | t = 5 |
|---|---:|---:|---:|---:|---:|
| WEB | 41.9 | нет данных | 48.3 | 48.8 | 49.3 |
| DBS | 57.4 | 55.4 | 53.4 | 51.4 | 54.8 |
| IOP | 30.2 | 29.5 | 34.1 | нет данных | 32.6 |

### 4.2. Структуры данных

Для хранения записей журнала инцидентов и рядов компонентов используются структуры с одномерными массивами:

```c
typedef struct {
	int time;               /* номер отсчёта */
	int type;               /* тип инцидента */
} Incident;

typedef struct {
	char name[NAME_LEN];        /* код компонента */
	float values[MAX_MEASURE];  /* измеренные значения */
	int times[MAX_MEASURE];     /* номера отсчётов */
	int count;                  /* число измерений */
	double q_vals[POINT_COUNT]; /* значения показателя Q */
	int codes[POINT_COUNT];     /* коды результата расчёта */
	int states[POINT_COUNT];    /* состояния по отсчётам */
} Component;
```

### 4.3. Функции программы

Программа в `main.c` разделена на функции:

- `calc_q` — вычисляет $Q = \ln(X[i] / X[i-k])$, проверяет деление на ноль и знак отношения; возвращает код результата (`CALC_OK`, `CALC_DIV_ZERO`, `CALC_BAD_LOG`) и записывает значение по указателю `*pq`;
- `check_component` — обрабатывает измерения одного компонента при заданных `k` и `limit`, заполняет массивы `q_vals`, `codes`, `states` и возвращает число успешно рассчитанных `Q`;
- `is_incident` — реализует логическое правило одновременной тревоги трёх компонентов;
- `find_incidents` — сканирует отсчёты и заполняет журнал `Incident incidents[]`;
- `print_component_rows` и `print_results` — выводят таблицу расчёта `Q`, таблицу состояний по отсчётам и журнал инцидентов;
- `run_analysis` — подготавливает выбранный набор данных (1 — контрольный набор варианта 25; 2 — тестовый набор с ошибками и инцидентом) и запускает анализ;
- `state_name` — возвращает текстовое название состояния;
- `read_int_range` и `read_positive_double` — выполняют безопасный ввод пунктов меню и параметров `k`, `L`.

## 5. Алгоритм и блок-схема

1. **Начало**.
2. Задать параметры по умолчанию: $k = 1$, $L = 1.0$, набор данных `1`.
3. Вывести меню режимов работы и считать выбор пользователя `choice`.
4. При `choice == 1`: рассчитать `Q[i]` по парам $X[i]$ и $X[i-k]$ для `WEB`, `DBS`, `IOP` с пропуском первых $k$ элементов и проверкой ошибок, определить состояния, найти инциденты и вывести результаты.
5. При `choice == 2..5`: сменить набор данных, задать $k$, задать $L$ или сбросить настройки.
6. При `choice == 0`: завершить работу; при неверном вводе вывести сообщение об ошибке и повторить меню.
7. **Конец**.
